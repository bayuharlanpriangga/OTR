## Current Architecture
- Vanilla HTML/CSS/JS, ES Modules, tanpa framework/build step.
- Routing: hash-based (`#/reading`, dst), didaftarkan di `js/app.js` via `registerRoute()`.
- State: satu object global di `js/core/state.js`, diakses via `getState()`/`setState()`/`patchState()`.
- Komunikasi antar modul lewat `js/core/event-bus.js` (event: `route:change`, `toast:show`, `state:change`).
- Halaman = modul dengan `export default { render(container, params) }`, di-load lazy lewat dynamic `import()`.
- Data domain tarot independen dari UI (`data/`), dikonsumsi Tarot Engine (`js/tarot/`) tanpa DOM sama sekali.
- **Tarot Engine (`js/tarot/`) juga independen dari state management/UI** — `tarot-engine.js` tidak meng-import `js/core/state.js` atau `event-bus.js`. Layer di atasnya (`js/pages/reading.js`, Phase 5) yang menyambungkan hasil `engine.getReading()` ke `patchState("reading", ...)`. Keputusan ini menjaga engine tetap testable murni lewat `node` tanpa DOM/browser — terbukti berguna waktu memverifikasi bugfix lokasi folder di awal Phase 5 (lihat Known Issues).
- `js/tarot/` sekarang benar-benar berada di `js/tarot/` (dipindah dari root repo di awal Phase 5 — lihat Completed & Known Issues), sesuai Master Spec §3.
- **`js/tarot/interpretation.js` (Phase 6) mengikuti pola independensi yang sama** — fungsi murni, tidak import `state.js`/`event-bus.js`, tidak tahu apa itu `TarotEngine`. Dipanggil langsung oleh page controller (`reading.js` & `result.js`), sejajar dengan `tarot-engine.js` — bukan lapisan di atas/di bawahnya. `TarotEngine` menangani *fisik* reading (deck, draw, status), `interpretation.js` menangani *makna* dari kartu yang sudah ditarik; keduanya tidak saling import.
- Struktur folder & nama file mengikuti Master Spec §3 persis.

## Important Decisions
- Router pakai hash (`#/...`), bukan History API — supaya kompatibel static hosting tanpa rewrite rule.
- Font: Fraunces (display) + Public Sans (body) + IBM Plex Mono (data/angka) via Google Fonts CDN.
- Palet warna "night-reading table": obsidian/plum sebagai ruang, gold sebagai foil-accent, oxblood untuk state reversed/destructive.
- Data Minor Arcana (56 kartu) di-generate dari kombinasi tema suit × tema rank/court, bukan ditulis satu-satu manual. Teks Major Arcana (22 kartu) ditulis individual.
- `tarot-keywords.js` sengaja dipisah dari `tarot-cards.js` supaya fitur search/filter (Phase 9) & quiz (Phase 21) bisa jalan tanpa nge-load seluruh teks upright/reversed 78 kartu.
- `image` path memakai format `/assets/images/tarot/{suit-or-major}/{slug}.webp` — placeholder, asetnya diisi di Phase 4.
- **Randomization pakai `crypto.getRandomValues()` dengan rejection sampling** (bukan modulo langsung) supaya distribusi shuffle/orientation tidak bias ke angka kecil — sesuai Master Spec §10. Fallback ke `Math.random()` hanya kalau Web Crypto API benar-benar tidak tersedia di environment.
- **`TarotEngine` sengaja dipisah dari `TarotDeck`**: `deck.js` cuma tahu soal kartu fisik (draw/shuffle/reset), tidak tahu apa itu "reading" atau "spread". `tarot-engine.js` yang mengorkestrasi deck + orientation + spread jadi satu reading entity. Pemisahan ini supaya tiap modul gampang dites sendiri-sendiri (lihat runtime test Phase 3).
- **Reveal dipisah jadi state tersendiri dari draw** (`drawing` → `revealing` → `interpreting`), bukan digabung jadi satu langkah — mengikuti state machine Master Spec §15 dan mencegah UI (Phase 5) "skip" langsung dari draw ke interpretasi tanpa render animasi reveal.
- **`drawCard()` mengembalikan objek kartu penuh** (`card`, hasil resolve dari `getCardById`), tapi yang disimpan permanen ke `reading.cards` hanya `{ positionId, cardId, orientation }` — konsisten dengan schema Reading Entity Master Spec §14 (tidak menyimpan data kartu yang sudah redundan dengan `data/tarot-cards.js`).
- **`js/components/tarot-card.js` sengaja tidak tahu apa-apa soal `TarotEngine`** — komponen cuma nerima props data kartu + flag state. Pemisahan ini konsisten dengan pola yang sudah dipakai di Phase 2 & 3 (data/logic independen dari UI): Phase 5 nanti yang jadi "lem" antara `engine.drawCard()` dan `renderTarotCard()`.
- **Reversed orientation memutar seluruh wajah kartu 180°** (bukan cuma teks atau cuma artwork) — meniru tampilan kartu tarot fisik yang benar-benar terbalik, bukan sekadar ikon "reversed" di kartu yang tetap tegak. Badge kecil di pojok (tidak ikut rotasi) yang menjaga keterbacaan status orientasi.
- **Background art kartu pakai CSS `background-image` di sebuah `<div>`, bukan `<img>`** — karena `image` path di `data/tarot-cards.js` masih placeholder (aset `.webp` belum ada, lihat Known Issues Phase 2/3). Dengan `background-image`, gambar yang gagal load tidak memunculkan broken-image icon; huruf awal nama kartu (`.tarot-card__art-fallback`) selalu jadi fallback yang terlihat sengaja, bukan rusak. Begitu aset asli tersedia, tidak perlu ubah komponen — tinggal isi file di path yang sudah direferensikan.
- **`js/pages/reading.js` sengaja membuat `TarotEngine` baru tiap kali `render()` dipanggil** (bukan singleton module-level yang dipertahankan lintas navigasi) — navigasi ke `#/reading` = mulai reading baru, konsisten dengan mental model "reading" sebagai sesi sekali jalan. State reading yang **sudah selesai** dipertahankan lewat `js/core/state.js` (bukan lewat instance engine), supaya Result Page bisa dibaca ulang tanpa bergantung ke module reading.js.
- **Kategori interpretasi (general/love/career/spiritual) dipilih di step Pertanyaan, bukan otomatis dari spread** — walau tiap spread punya `category` default (dipakai sebagai nilai awal `<select>`), user tetap bisa override. **Bugfix (ditemukan lewat smoke test manual pertama di browser sungguhan, pasca-Phase 7): kartu tidak animasi flip sama sekali — langsung terbuka tanpa transisi.** Root cause di `js/components/tarot-card.js` (Phase 4), bukan CSS: `reveal()`/`hide()` men-set `data-revealed` lalu langsung memanggil `rerender()` (`container.innerHTML = tarotCardHTML(state)`), yang mengganti seluruh elemen kartu dengan elemen DOM baru yang *sudah* lahir dalam state akhirnya. Karena browser tidak pernah melihat perubahan atribut pada elemen yang sama di antara dua frame, CSS transition di `.tarot-card__inner` (`tarot-card.css`) tidak punya apa pun untuk di-animasikan — kartu langsung snap ke hasil akhir. Ini bug yang sudah ada sejak Phase 4/5 tapi lolos dari seluruh runtime test `jsdom` sebelumnya karena test-test itu cuma memverifikasi atribut akhir (`data-revealed === "true"`, dst), bukan memverifikasi identitas elemen DOM sebelum & sesudah — jsdom juga tidak mengeksekusi CSS transition sama sekali, jadi kelas bug ini secara struktural tidak mungkin ketahuan lewat `jsdom`, cuma lewat browser sungguhan.
  - Diperbaiki dengan membuat `reveal()`/`hide()` memutasi elemen yang sudah ter-mount secara langsung (`dataset.revealed`, `aria-label` via `setAttribute`) alih-alih memanggil `rerender()`.
  - Badge orientasi "Terbalik" (sebelumnya cuma masuk markup kalau `revealed && orientation === "reversed"`, yang berarti butuh rerender penuh untuk muncul) sekarang selalu ada di DOM saat `orientation === "reversed"` — visibilitasnya sebelum reveal tetap otomatis tersembunyi lewat mekanisme `backface-visibility: hidden` yang sama yang menyembunyikan seluruh wajah depan kartu (badge itu child dari `.tarot-card__front`), bukan lewat kondisi markup. Atribut `aria-hidden` di-toggle manual saat reveal/hide supaya screen reader tidak membaca teks "Terbalik" sebelum kartu benar-benar dibuka.
  - `setOrientation()`/`setDisabled()`/`update()` tetap memakai `rerender()` — aman karena ketiganya dipanggil di luar momen animasi flip (sebelum kartu di-reveal, atau mengganti kartu yang masih tertutup).
  - Ditambahkan `buildAriaLabel()` sebagai helper bersama, dipakai baik oleh `tarotCardHTML()` (di-escape untuk HTML) maupun `reveal()`/`hide()` (raw, lewat `setAttribute` yang tidak butuh escape) — supaya logic label tidak duplikat di dua tempat dan bisa saling konsisten.
  - Diverifikasi lewat `test_reveal_flip_fix.mjs` (`jsdom`, one-off, tidak ikut deliverable): 18/18 assertion, termasuk assertion inti "`handle.el` sebelum dan sesudah `reveal()` adalah elemen DOM yang sama (`===`)" — cek yang sebelumnya tidak pernah ditulis di test manapun dan yang seharusnya menangkap kelas bug ini kalau ada di masa depan.
